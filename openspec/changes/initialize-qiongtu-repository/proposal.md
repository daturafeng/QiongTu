## Why

穹图当前的 OpenSpec 与开发规则位于一个尚未受版本控制的父目录中，后续会话无法通过仓库稳定恢复上下文，也没有可追溯的变更历史。现在应在产品开发开始前建立独立的 `QiongTu` 项目根目录，并把经过审核的项目工件发布到用户已创建的空 GitHub 仓库。

目标用户是项目所有者与后续参与开发的会话/协作者；预期价值是获得单一、可克隆、可审计的项目入口。成功标志为本地 `main` 分支与 `origin/main` 同步、工作区干净、OpenSpec 严格校验通过，并且仓库不包含原始航拍影像、密钥或大型派生成果。

## What Changes

- 在当前工作区父目录下创建独立的 `QiongTu` 项目目录，并仅迁移现有 `AGENTS.md`、`.codex/` 与 `openspec/` 项目工件。
- 增加简明的 `README.md` 作为项目入口，明确产品定位、当前状态及 OpenSpec 唯一事实来源。
- 增加 `.gitignore`，默认排除密钥、本机环境文件、依赖、构建缓存、原始输入和大型处理成果。
- 初始化默认分支为 `main` 的 Git 仓库，配置 `origin` 为 `https://github.com/daturafeng/QiongTu.git`，提交并推送已审核内容。
- 保持用户指定的仓库外无人机参考数据只读且不移动、不改写、不纳入版本控制。
- MVP 是一个可克隆、可校验并能由后续会话继续工作的最小项目仓库；本变更不实现影像重建、桌面界面、后端服务、构建流水线或产品发布。

## Capabilities

### New Capabilities

- `repository-bootstrap`: 规定穹图项目根目录、Git/GitHub 连接、公开仓库内容边界和可恢复项目入口的可验收行为。

### Modified Capabilities

无。

## Impact

- **目录与数据**：现有三个项目工件将从父目录迁入 `QiongTu`；仓库外影像与用户其他文件不受影响。
- **版本控制**：建立首批公开 Git 历史并推送到用户指定的 GitHub 仓库；提交作者沿用用户现有 Git 配置。
- **外部依赖**：依赖本机 Git、Git Credential Manager/现有 GitHub 登录状态，以及 NVM 下 Node.js 22.23.1 对应的 OpenSpec 1.7.0。
- **许可**：本次不选择或新增开源许可证；公开可见不等于授予复用许可，后续需由项目所有者单独决策。
- **隐私与安全**：只提交治理与产品定义工件；禁止提交令牌、许可证、机器专属配置、原始航拍数据和大型输出。
- **交付约束**：远端当前为空；若身份验证或网络失败，本地仓库保持可恢复状态并如实保留未完成任务，不使用其他账户或覆盖用户 Git 配置。
