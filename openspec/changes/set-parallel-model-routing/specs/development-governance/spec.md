## MODIFIED Requirements

### Requirement: 并行开发必须由单一总控按 OpenSpec 任务协调
当多个 Codex 窗口同时参与项目时，项目 MUST 指定一个总控窗口维护任务依赖、写入所有权、集成顺序、验证与 OpenSpec 状态。当前活动总控窗口 SHOULD 默认使用 GPT-5.6；由总控创建的新执行窗口 SHOULD 默认使用 GPT-5.5。每个执行窗口 MUST 只处理明确分配的任务编号、输入、允许路径和验收范围，不得自行扩大任务或建立与 OpenSpec 竞争的事实来源。总控 MUST 只为不依赖同一未决决策、写入不重叠且能独立验收的任务创建并行窗口，不得以窗口数量代替实际进度。

#### Scenario: 创建并行执行窗口
- **WHEN** 总控识别出不依赖同一未决决策且可独立验收的任务，并且 GPT-5.5 在当前 Codex 模型目录中可用且允许设置模型覆盖
- **THEN** 总控使用 GPT-5.5 创建执行窗口，提供任务编号、边界、允许修改路径、验证命令和阻塞升级条件，并持续保留最终集成责任

#### Scenario: 指定执行模型当前不可用
- **WHEN** GPT-5.5 不在当前模型目录、模型目录在 Codex 启动后变化、运行时明确禁止模型覆盖或创建窗口失败
- **THEN** 总控不静默改用其他模型、不重复无变化的创建操作；总控可串行推进安全工作，并记录需要重启 Codex 或由用户解除的条件

#### Scenario: 任务没有实际并行收益
- **WHEN** 候选任务依赖同一未决决策、需要修改重叠文件或不能独立验收
- **THEN** 总控保持串行执行或重新划分边界，不为该任务创建额外窗口

#### Scenario: 并行任务返回结果
- **WHEN** 执行窗口完成实现或研究
- **THEN** 总控复核证据、在目标基线上重新验证并完成集成后，才更新对应 OpenSpec 状态或采用研究结论
