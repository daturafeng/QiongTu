## Why

无人机航拍会产生大量相互重叠、带有位置与姿态信息的照片，但用户需要一套类似大疆智图的本地生产工具，把原始影像稳定转换为平面底图、点云、标准三维模型、流式 3D Tiles 和高保真三维高斯成果。本变更建立完整产品边界，并特别保证高斯成果能够在 Cesium 中按地理坐标和层级细节加载。

## What Changes

- 建立面向 Windows 工作站的本地摄影测量生产软件，以“项目—数据集—处理任务—成果”为核心工作流。
- 建立不依赖单一用户样例的多来源验收数据集组合，覆盖规则正射、倾斜建筑/复杂场景、带独立控制或参考成果的精度验证、三维高斯新视角质量以及确定性故障输入；每个外部数据集必须记录来源、用途、许可和再分发边界。
- 公开仓库只保存所有者样例的逻辑别名、适用角色和私有清单绑定，不发布其内容指纹、数量/大小、设备型号、拍摄分布、相对范围或时长；详细清点仅保存在 Git 忽略的本地工件中。
- 支持导入无人机 RGB 影像、JPEG/MPO 多帧容器、EXIF/XMP/GPS 元数据及同批次 RTK/导航辅助文件，并在处理前完成覆盖度、重叠度、清晰度、定位信息等质量检查。
- 建立共享空三结果的摄影测量处理流水线，生成稀疏点云、稠密点云、DSM、二维正射影像、带纹理三维网格和三维高斯模型。
- 支持选择坐标参考系；为后续接入地面控制点、RTK/PPK 和测绘级精度校正预留边界。
- 提供任务排队、进度、日志、失败原因、取消和可恢复重试能力，以应对长时间、高算力处理。
- 提供二维/三维成果浏览、基础量测、质量报告和标准格式导出能力；平面成果支持 GeoTIFF，点云支持 LAS/LAZ/PLY，纹理网格支持 OBJ/FBX。
- 生成独立的网格 3D Tiles 成果，以 `tileset.json` 和分层 glTF/GLB 内容提供地理定位与 LOD 流式加载。
- 保存可重新转换的原始高斯成果，并生成采用 `KHR_gaussian_splatting`、`KHR_gaussian_splatting_compression_spz_2` 与 SPZ 压缩的 Cesium 高斯 3D Tiles；成果 SHALL 可由兼容版本的原生 CesiumJS 加载，无需修改 Cesium 源码。
- 将首版范围限定为离线批处理的可见光航拍影像；实时建模、飞控、航线规划、多光谱/热红外分析、自动目标识别和完整 GIS 编辑不纳入首版。

## Capabilities

### New Capabilities

- `project-dataset-management`: 管理项目、数据集、影像元数据、坐标参考系和成果生命周期。
- `imagery-ingestion-quality-control`: 导入无人机影像及定位辅助文件，识别真实容器与摄影测量主帧，校验元数据、清晰度、重复影像、定位信息、覆盖和重叠风险，并生成可操作的质检结果。
- `photogrammetry-processing`: 编排共享空三、点云、表面模型、正射校正、纹理网格和三维高斯训练流程。
- `processing-job-operations`: 管理长时计算任务的排队、资源状态、进度、日志、取消、失败恢复和重试。
- `geospatial-output-management`: 管理二维正射底图、DSM、点云、OBJ/FBX、网格 3D Tiles、原始高斯和 Cesium 高斯 3D Tiles 的坐标、版本、质量信息与导出。
- `map-model-viewing-measurement`: 在二维地图和 Cesium 三维场景中浏览网格、点云和高斯成果，切换图层并执行适用的基础位置、距离、面积和高程量测。

## Impact

- 新建产品的领域模型、处理服务、任务调度、对象存储、空间元数据和二维/三维客户端。
- 需要评估摄影测量引擎、GIS/三维渲染组件、坐标转换库以及 GPU/CPU 计算资源的许可、性能和部署方式。
- 三维高斯训练需要独立的 GPU 处理分支、模型清理、压缩、空间分块和 LOD 生成能力；高斯格式与 Cesium 支持仍处于快速演进期，必须固定兼容版本并保留重新转换能力。
- 原始影像与派生成果体积可能达到数 GB 至数百 GB，存储成本、本地导入可靠性、断点恢复、成果切片和生命周期清理会成为关键系统约束。
- 引擎和参数选型必须通过多个相互独立、许可可核验的数据源，不能以 `owner-oblique-sample-v1` 或任何单一数据集的成功代替泛化与兼容性证据。
- 精度依赖飞行高度、相机、重叠度、纹理、GPS/RTK/PPK 与地面控制点；产品必须区分“可视化级”和“测绘级”结果，不能承诺脱离输入条件的固定精度。
