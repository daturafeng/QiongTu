## Context

参见 `proposal.md` 的动机。当前父目录不是 Git 仓库，只包含 `AGENTS.md`、`.codex/` 和 `openspec/` 三个项目工件；目标子目录尚不存在，指定 GitHub 公共仓库已经只读确认为空。OpenSpec CLI 位于 NVM 管理的 Node.js 22.23.1 目录中，当前 PATH 不含该命令。用户指定的仓库外参考数据属于高价值源数据，必须保持只读和版本控制外状态。

## Goals / Non-Goals

**Goals:**

- 以可检查、限定目标的方式把现有项目状态迁入独立根目录。
- 建立最小但安全的公开 Git 仓库边界，并验证本地与远端一致性。
- 让克隆仓库后的后续会话能从固定入口恢复 OpenSpec 工作流。
- 在任一步失败时保留可恢复的本地项目状态和真实任务状态。

**Non-Goals:**

- 不搭建产品代码、依赖、CI/CD、制品发布或数据处理流水线。
- 不导入、复制或扫描参考影像内容，不选择软件许可证。
- 不修改全局 Git 配置、GitHub 仓库设置、NVM 当前版本或用户浏览器状态。

## Decisions

### 使用父目录下的 `QiongTu` 作为唯一项目根目录

先解析父目录与目标目录的绝对路径，确认目标严格位于父目录内且尚不存在，再创建目标目录。迁移使用固定白名单 `AGENTS.md`、`.codex`、`openspec` 的逐项 `Move-Item -LiteralPath`，不使用通配符或递归扫描。

选择该方式是因为它与 GitHub 仓库名一致，且能避免把父目录未来可能出现的无关文件带入仓库。备选方案是在父目录直接初始化 Git，但会让仓库边界与用户明确确认的子目录方案不一致；复制而非移动则会留下两个可能分叉的 OpenSpec 事实来源，因此均不采用。

### 用最小入口文件建立公开仓库边界

新增 README 只记录产品定位、阶段和 OpenSpec 链接，不复制需求或设计。`.gitignore` 按类别排除环境密钥、IDE/系统文件、日志临时文件、依赖/构建缓存，以及约定的输入、输出、工作区、检查点和模型目录；不全局忽略图片或三维格式扩展名，以免未来合法的小型测试资产无法受控提交。

备选方案是立即生成完整工程脚手架，但产品技术栈尚由活动产品定义变更管理，提前创建代码会越过 OpenSpec 门禁。

### 沿用现有 Git 身份并使用 HTTPS 远端

本地仓库使用 `git init -b main`，远端地址使用用户提供的 HTTPS URL。提交作者沿用现有全局配置，不在仓库内猜测或覆盖身份；认证交给 Git Credential Manager 和用户现有 GitHub 会话处理。

备选 SSH 远端需要确认本机密钥与账户绑定，当前没有必要；通过浏览器手工上传会失去可重复的本地 Git 操作和跟踪分支，因此不采用。

### 推送前后都执行可审计检查

推送前检查暂存文件、统计、空白错误和文件大小，执行 OpenSpec 全量严格校验；首个提交推送成功后，再同步并归档本次 bootstrap 变更，使用第二个小提交记录归档状态并再次推送。最终以分支跟踪、工作区状态、远端引用和 OpenSpec 状态共同验收。

这比把归档状态混入未经远端验证的首个提交多一个小提交，但能让任务状态保持真实：远端发布先被验证，随后才归档完成的变更。

## Risks / Trade-offs

- **[目录迁移中断]** → 仅移动三个已验证的绝对目标；每一步后检查目标和源位置。若推送前失败，依据实际存在位置逐项恢复，不做递归删除。
- **[公开仓库意外泄露]** → 使用 `.gitignore`、暂存清单与文件大小审查；不读取或复制仓库外影像，不提交环境与凭据文件。
- **[GitHub 认证或权限失败]** → 保留本地提交，停止在推送任务并报告错误；不更换账户、不修改凭据或仓库可见性。
- **[全局 Git 邮箱并非 GitHub 验证邮箱]** → 不擅自修改身份；提交仍可推送，但归属显示由 GitHub 对该邮箱的识别决定，并在交接中说明。
- **[尚无开源许可证]** → README 不作授权承诺；许可证选择作为后续产品/治理决策进入 OpenSpec。

## Migration Plan

1. 校验父目录、目标目录和固定迁移清单，创建 `QiongTu` 后逐项移动。
2. 添加 README 与忽略规则，更新必要的 OpenSpec 项目上下文并严格校验。
3. 初始化 `main`、配置 `origin`，审核并创建首个提交。
4. 推送并验证 `origin/main`；失败则保留本地提交和未完成任务供重试。
5. 在成功验证后同步并归档本变更，提交归档记录，再推送并执行最终一致性检查。

回滚仅在远端首次推送前适用：若需要恢复旧布局，先验证三个目标均只属于本次迁移，再逐项移动回父目录并移除空的目标目录。首次推送后不删除远端历史；任何后续撤销通过新的 OpenSpec 变更和可追溯 Git 提交完成。
